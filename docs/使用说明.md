# AUTOSAR ECUC Bridge 使用说明

这是一个本地桥接工具：它把一条 JSON 请求交给你本机已经合法安装的 DaVinci Configurator。它不携带 DaVinci、SIP、许可证，也不替代你在 DaVinci 中理解配置的责任。

## 1. 先准备一次

1. 安装与你项目匹配、且已获授权的 DaVinci Configurator 与 SIP。
2. 编译本项目，或下载本项目发布页中的两个 Windows 程序：`lgk-vector.exe` 与 `lgk-vector-host.exe`。两个文件必须放在同一文件夹。
3. 在项目的 `Cfg` 目录中新建 `lgk-vector.json`。它只描述本项目，不要放在上级目录：

```json
{
  "tool_path": "D:\\Vector\\SIP"
}
```

新工程不必填写 `project_path`，工具直接使用 JSON 所在的 `Cfg` 目录；保留旧字段时，它仍必须与该目录完全一致。默认情况下，目录中应有唯一一个 `.dpa`，`tool_path` 下应能找到唯一一个 `DVCfgCmd.exe`。如果同一目录保存了多个工程文件，或电脑上并存多个 DaVinci 命令程序，可以明确指定：

```json
{
  "tool_path": "D:\\Vector\\SIP",
  "project_file": "VehiclePlatform.dpa",
  "davinci_command_path": "D:\\Vector\\DaVinci\\Exec\\DVCfgCmd.exe"
}
```

`project_file` 必须位于当前 Cfg 目录内并以 `.dpa` 结尾，可使用相对路径；`davinci_command_path` 必须直接指向 `DVCfgCmd.exe`，相对路径按 `tool_path` 解析。这两个字段都是可选项，不填写时仍按唯一候选自动发现。

这个桥接器不绑定 TC275，也不把模块包固定为 `MICROSAR`。它先从所选 DPA 找到模块配置文件，再从实际 ECUC 的 `DEFINITION-REF` 取得模块定义路径，最后到当前 SIP 中匹配 BSWMD。单模块生成同样使用这个真实路径。因此换成 TC3xx、S32K 或其他目标平台时，桥接器本身不需要增加芯片分支；前提是目标工程、DaVinci 版本和 SIP 本来就彼此兼容。

## 2. 最常用的调用方式

推荐使用 D 盘中央源码提供的 PowerShell 包装器。所有 AUTOSAR 工程共用这一份工具，不要在工程目录复制程序或源码。它把长 JSON 写入临时请求文件，避免 PowerShell 对引号的处理造成请求损坏。
包装器还会先用一个独立进程启动 resident host，再发送业务请求，避免把 DaVinci 首次加载绑在 host 启动进程上。

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\MyProject\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"find_module","module":"Com"}'
```

每个会话结束时都要正常关闭常驻 host：

```powershell
& "D:\Tools\LGK-Vector\scripts\Invoke-LGKVector.ps1" `
  -ProjectPath "D:\Work\MyProject\Proj_Config\Bsw_Config\Cfg" `
  -Request '{"func":"shutdown_host"}'
```

不要使用任务管理器或强制结束进程代替这条请求。切换项目时也应先关闭原项目的 host。

## 3. 一次 COM 配置修改应该怎样做

下面是一个安全且快的顺序。已知目标时不需要把整个 COM 模板和所有错误都读出来。

1. 已知配置容器时，可先用本地只读请求查看当前落盘值：`{"func":"inspect_ecuc_containers","module":"Com","container":"ComSignal","params":["ComBitPosition"]}`。它不启动 DaVinci。
2. 找模块：`{"func":"find_module","module":"Com"}`。
3. 不清楚参数定义时，查一个参数：`{"func":"get_param_definition","module":"Com","params":"ComBitPosition"}`。
4. 不清楚实际容器位置时，按刚返回的 `definition_ref` 定位。下面的 `/MICROSAR/...` 只是一个示例，实际调用应原样使用查询结果，不要手写供应商前缀：

```json
{
  "func": "locate_container",
  "module": "Com",
  "definition_ref": "/MICROSAR/Com/ComConfig/ComSignal",
  "short_name_regex": "^MySignal$"
}
```

5. 保存并关闭 DaVinci GUI 中的同一工程，人工查看返回行附近的 ARXML 原文，再用 `edit_file` 进行最小行范围替换。该工具拒绝编辑 `project_path` 之外的文件。
6. 只为变动的模块生成：`{"func":"generate_code","module":"Com"}`。生成成功就是这次 ECUC 改动的首要验证结果。
7. 如果生成失败，再查：`{"func":"get_errors_list","module":"Com"}`。不要因为“快”就自动修错误；有自动操作时，先看错误和影响，再显式传 `confirmed:true` 执行 `auto_solve_errors`。

## 4. 函数速查

| 请求 | 用途 | 何时用 |
| --- | --- | --- |
| `inspect_ecuc_containers` | 本地读取已保存的 ECUC 容器和值 | GUI 打开或要快速核对当前值时 |
| `find_module` | 找实际 ECUC 模块文件 | 不确定模块是否存在时 |
| `find_module_template` | 查看轻量模块模板层级 | 要新增未知 container/reference 时 |
| `get_param_definition` | 查参数的 definition ref、值类型 | 需要准确创建或定位参数时 |
| `locate_container` | 找真实 container 与行号 | 编辑前定位实际 block 时 |
| `edit_file` | 最小文本替换 | 已确认原文和行范围后 |
| `get_errors_list` | 获取 DaVinci 校验错误 | 生成失败或明确要求诊断时 |
| `auto_solve_errors` | 执行已确认的 DaVinci 自动操作 | 你已审阅错误并明确确认时 |
| `generate_code` | 对一个模块或全部模块生成 | 配置改完后 |
| `shutdown_host` | 正常释放常驻 DaVinci 会话 | 最后一步、切换项目之前 |

兼容旧自动化的三个名称 `find_bsw_module`、`get_bsw_module_template`、`get_bsw_param_definition` 仍可调用；新脚本请使用表中的简短名称。

## 5. 怎样保持速度

- 同一项目连续处理时复用常驻 host，不要每条请求都重新启动 DaVinci。
- 已知 container 和参数时，直接做局部定位、修改、单模块生成。
- 仅在生成失败或你明确要诊断时读取错误清单；不要默认扫全工程。
- 不要用“生成全部模块”代替受影响模块生成。
- 最后一定 `shutdown_host`，避免下次项目意外复用旧会话。

工具启动、加载 DaVinci 工程和真正的代码生成仍取决于 DaVinci 与项目本身；本工具只避免重复启动、重复扫描和不必要的全量生成，不能承诺比 DaVinci 自身更快。

## 6. 公开协作边界

向本项目提交代码前，删除客户 ARXML、SIP 文件、许可证、账号信息、原厂二进制、反编译输出和从受限产品中提取的脚本。新功能应基于公开文档、合法安装的本地工具和可分享的测试夹具独立实现。发现知识产权问题时，请走仓库托管平台的私密举报或维护者公布的联系渠道；处理方式是及时下架或替换有争议内容，而不是把受保护内容作为默认发布物。
